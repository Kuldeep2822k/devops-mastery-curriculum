# Review Questions — Module 03 Git

Answer from memory first.

1. Explain Git commits/trees/blobs in one paragraph. What does a branch point to?
2. What is HEAD? What does “detached HEAD” mean operationally?
3. When is it safe to rebase? When is it unsafe?
4. Compare revert vs reset vs cherry-pick for a production rollback scenario.
5. Describe a conflict resolution process that avoids “take ours” guessing.
6. What is reflog and what problems does it solve?
7. Define “known good” and “known bad” for bisect. What makes a bisect signal valid?
8. Why do flaky tests break bisect? What alternatives can you use?
9. What makes a good release tag policy? Why prefer annotated tags?
10. What information should a PR description include for operational quality?
11. How can commit structure reduce MTTR during incidents?
12. Describe a safe hotfix workflow from a release tag.
